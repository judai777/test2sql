## 变更内容

**环境**
- 新建 conda 环境 `t2s`（Python 3.11.16），安装 httpx / pydantic / sqlglot / pytest / faker。
- **偏差记录**：design.md 技术栈写的是"uv 新环境"。实际 uv 0.12.7 已装入系统 Python，但其托管 Python 3.11 下载被网络阻断（GitHub 直连不稳），改用机器上现成的 conda 建 3.11 环境。pyproject.toml 保持与 uv 兼容，网络允许时可一条 `uv sync` 切回。

**数据规模**：共 2,186,759 行——trades 100 万、orders 45 万、quotes_daily 25.9 万、fund_nav 20 万、settlements 12 万、holdings 5 万、margin_trades 5 万、customers 1.5 万、risk_alerts 1.5 万、accounts 2.5 万、products 3 千、branches 30。

## 过程中修复的缺陷（自测记录）

1. `holdings` / `settlements` 两张表 INSERT 占位符数量与列数不符（8 对 7），首次运行报 `OperationalError`。
2. holdings 每快照日生成系数少一个数量级（5k vs 50k），修正后 4,991 → 49,979 行。

## 验证结果

- 12 表行数统计齐全，总量 2,186,759。
- 三表 JOIN 分析查询（近一月各营业部成交额 Top5）耗时 1~3 秒——**达到 M0 完成判据**（"一条 SQL 在库上跑通且耗时可观"，LIMIT/超时护栏由此有真实意义）。
