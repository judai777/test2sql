# CHG-006：M5 落地——golden 评测集、结果集比对与记忆消融框架

- 日期：2026-08-29
- 动机：执行 `docs/design.md` §10 里程碑 M5，PRD FR-9 / NFR-4——产出面试硬数字的基础设施。
- 类型：新增

## 变更内容

| 文件 | 说明 |
|---|---|
| `eval/golden.jsonl` | **golden 集 50 条**，五档分层：单表 15 / 多表 JOIN 15 / 聚合 10 / 时间口径 5 / 歧义澄清 5。每条含 question、golden_sql、judge（result_match / valid_sql） |
| `eval/runner.py` | 评测运行器：结果集比对（**多集合比对 + 有序比对**自动按金标是否含 ORDER BY 切换；数值 4 位舍入容差）、语法有效率、平均步数/token、分档准确率、`--no-memory` 消融开关、`--verify-golden` 离线金标校验、JSON 报告落盘 `eval/reports/` |
| `eval/reports/eval-memory.db` | 评测专用会话/审计库——**不污染用户记忆库**；评测期间新沉淀的样例在结束后自动回收 |
| `tests/test_eval.py` | 9 例：多集合/有序/浮点容差比对、汇总数学、golden 结构（50 条五档）、runner 端到端（含错表案例）、valid_sql 档判定、澄清亦算通过；真实 LLM 冒烟标记 `eval`，无 key 自动 skip |
| `pyproject.toml` | pythonpath 增加 `.`（eval 包可导入） |

**关键设计**：
1. **结果集比对而非 SQL 文本比对**（design.md §9）：agent 的写法与金标不同但结果一致即算对——对 LLM 更公平；
2. **歧义档判定宽严有别**：X01（月活跃）有金标按结果比对（口径库注入是其自变量），X02~X05 判 valid_sql（澄清/声明假设/给出可执行 SQL 均通过）；
3. **消融闭环**：`--no-memory` 一键关闭记忆注入，同一 golden 集两跑相减即 Δ%——NFR-4 的"记忆消融相对提升 ≥5pp"有了测量仪器。

## 用法

```bash
PYTHONPATH=src python -m eval.runner --verify-golden   # 离线校验金标（无需 LLM）
PYTHONPATH=src python -m eval.runner --limit 5         # 真实冒烟
PYTHONPATH=src python -m eval.runner                   # 全量 50
PYTHONPATH=src python -m eval.runner --no-memory --tag ablation   # 消融组
pytest -m eval                                          # 真机冒烟进回归
```

## 验证结果

- `pytest`：**88 passed, 1 skipped**（skipped = 真实评测冒烟，无 key 自动跳过——预期行为）。
- **`--verify-golden`：50/50 金标 SQL 在真实 219 万行业务库上全部可执行**（M5 完成判据的离线部分达成）。
- ⏳ 真实准确率与消融 Δ% 待用户配置 `.env` 后运行全量评测产出（命令如上），预期写入本文件附录或新 CHG。

## 已知限制

- 时间口径档金标含显式日期（2026-08 等），随时间推移部分题目会自然失效——数据快照不变（合成库固定），故在 2026 年内稳定；跨年后应冻结库或刷新金标。
- 有序比对遇并列值（同额并排）可能因引擎 LIMIT 内部顺序不稳而误判——现 50 条中 ORDER BY 均为金额/数量级排序，并列概率可忽略。
- agent 端 LIMIT 100 与金标 200 行截断不一致的极端场景未处理（当前无题目结果集超 100 行）。
