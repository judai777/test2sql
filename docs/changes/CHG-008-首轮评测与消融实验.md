# CHG-008：首轮全量评测、比对器升级与记忆消融实验

- 日期：2026-08-29
- 动机：执行 PRD FR-9 / NFR-4——产出真实准确率基线与记忆消融 Δ%。
- 类型：新增（评测数据 + 比对器升级 + 一项失败模式修复）

## 一、实验设置

| 项 | 值 |
|---|---|
| 模型 | 智谱 glm-4.7（付费档，temperature 0.2） |
| 数据 | golden 50 条（五档分层），业务库 219 万行合成数据 |
| 组别 | 记忆开启（2 条演示问答 + 3 条口径种子）/ 记忆关闭（--no-memory） |
| 比对 | 结果集比对 v2（列名投影对齐 + 数值容差 + 限 10 的幂的量纲因子） |

## 二、结果

| 档位 | 记忆开 | 记忆关 |
|---|---|---|
| 单表 | 13/15 (87%) | 13/15 (87%) |
| 多表 JOIN | **10/15 (67%)** | 9/15 (60%) |
| 聚合 | 8/10 (80%) | **9/10 (90%)** |
| 时间口径 | 4/5 (80%) | 4/5 (80%) |
| 歧义澄清 | 4/5 (80%) | 4/5 (80%) |
| **整体** | **39/50 (78%)** | **39/50 (78%)** |

辅助指标：语法有效率 96%（两组同）；平均步数 8.3（开）/ 8.7（关）；平均 token 10,061 / 9,960。

**结论（诚实版）**：记忆系统在当前规模下整体 Δ≈0。逐案翻转 4↔4（A01/J02/J05/J10/J11/J14/S15 + S01 基础设施抖动），属温度 0.2 下的运行间方差，无一例可归因于记忆检索的实质帮助。

## 三、为什么 Δ≈0（归因）

1. **样例库规模不足**：仅 2 条演示对，few-shot 对 50 题的覆盖率天然有限——记忆的价值需要真实使用积累（这是"采纳闭环"设计存在的原因）。
2. **残余失败是系统性问题，few-shot 修不了**：J09（用清算表卖出额替代成交侧）、J12（流水 balance 求和≠期末余额口径）是语义口径错误；S06 是下述副作用；T05 是季度标签呈现差异。
3. **噪音量级**：N=50、单跑一次，±1~2 案即方差。

## 四、过程中的关键发现与修复

1. **few-shot 副作用（S06）**：记忆中存在相似问答时，模型把 SQL 抄在回答文本里直接作答、跳过执行验证（"30"为幻觉蒙对）。修复：system prompt 增加防抄条款（"参考记忆只能借鉴口径与写法，必须实际执行验证"）。
2. **比对器 v1 误判率高**：首跑 60% 中大量"同行数不一致"实为量纲（元 vs 亿元）、列形状（信息超集）、浮点表示差异。升级 v2：**列名投影对齐 + 数值 0.1% 容差 + 限 10 的幂的量纲因子（且 ≥2 行才启用，防单值任意比例假阳性）**。基线从 60% 修正为 78%——**18 个百分点的差距是评测公平性，不是模型能力**。
3. **S01 基础设施抖动**：DNS 瞬断（getaddrinfo failed）致一例未产出 SQL，非任务失败。
4. **真机冒烟计费防护**：`pytest -m eval` 改为需显式 `T2S_REAL_EVAL=1`，避免日常 pytest 意外计费。

## 五、迭代议程（下一轮实验）

1. 真实使用积累样例库（≥20 条高质量对）后重测消融——记忆的价值假设才能真正被检验；
2. 口径语义错误的对策实验：J09/J12 类错误注入口径库强化条目，观察是否改善；
3. 歧义档追问率统计（当前 X01 模型自选 7 月整月而非当月至今——澄清机制未被触发，值得专项分析）。
