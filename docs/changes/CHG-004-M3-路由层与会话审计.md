**路由决策流**（面试叙事主线）：
```
用户输入 → 权限初检(结构位) → 危险正则拦截(0 LLM) → LLM 意图分类
   ├─ chat       → 无工具直答
   └─ data_query → 会话落盘 → manager 装配历史窗口 → 引擎(ReAct) → 会话回写
任意出口 → 审计必录（拦截/失败也留痕）
```

## 设计澄清（ADR-005 修正）

原依赖表述 `manager→executor→{tools,llm,storage}` 不准确：管理层的会话/记忆职责必须访问存储。修正为——
`ui → router → manager → executor → {tools, llm}`，**storage 可被 manager 与 executor 访问**。ADR-005 文件已同步标注。

## 过程中修复的缺陷

1. **`_answer` 混用时钟域**：`elapsed_ms = time.time() - perf_counter()` 起点相减，数值天文数字（M2 遗留，测试未断言时长量级故漏网）——统一 perf_counter。
2. **`now_entry` 放错类**：定义在 AuditLog 上、调用方全用 `AuditEntry.now_entry`——构造辅助归位到模型。
3. ChatMessage 迁移时 tool_calls 的 pydantic 类型问题：`list[dict]` 会拒绝 ToolCall 对象，改为 `list[Any]` + to_api 鸭子类型序列化。

## 已知限制

- 危险词宽松匹配存在误拦可能（如"更新后的余额"不会误拦已收敛，但"插入语"类词形仍可能）；策略是 fail-safe，误报样本记入后续 CHG 收敛词表。
- chat 直答路径暂不计 token（审计 total_tokens=0），M5 评测时统一。
- 会话历史只存 user/assistant 轮次，工具明细留在 Answer.steps（审计含 steps 数）。

## 验证结果（M3 完成判据）

- PRD US-2（多轮指代）、US-4（危险请求拒绝+留痕）、US-7 前置（审计可查）在测试层达成。
