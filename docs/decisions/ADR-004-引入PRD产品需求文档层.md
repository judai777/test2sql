# ADR-004：引入 PRD 产品需求文档层

- 状态：**已接受**
- 日期：2026-08-29
- 提出人：用户（"针对grill-me拷打后，应该生成一份完整的PRD文档"）

## 背景

grill-me 收敛的九大决策散落在 ADR-001（决策视角）与 design.md（技术视角）中，缺少一份产品视角的权威文档：**做什么、给谁做、做到什么程度算好**。面试场景恰恰需要产品思维的证据（用户画像、用户故事、验收标准、成功指标），且后续每个功能点都需要 PRD 作为需求溯源。

## 决策

1. 新增 `docs/PRD.md` 作为产品需求权威文档（v1.0 已落盘）。
2. 文档层级固定为：`research/`（输入）→ **PRD（做什么）** → `design.md`（怎么做）→ ADR/CHG（变更）。
3. 冲突裁决遵循 ADR-002：最新 ADR/CHG > PRD ≈ design.md > research；需求变更走 CHG 并回写 PRD 对应条目。

## 备选与否决理由

- **design.md 单文档兼管产品**：技术与产品混杂，"为什么做"被"怎么做"淹没，面试讲产品时无据可引。
- **PRD 拆成多文件**：单人项目过度工程，单文件 + 章节锚点足够。

## 影响面

- `docs/PRD.md` 新增并登记主索引；里程碑定义以 design.md §10 与 PRD §9 双向对齐。
