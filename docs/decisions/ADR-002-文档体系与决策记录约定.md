# ADR-002：建立 docs/ 文档体系与决策记录约定

- 状态：**已接受**
- 日期：2026-08-29
- 提出人：用户（约定原文："每一次项目设计的决策都要落成为文档保存。每一次项目功能点的更改也要落地为文档保存。最好统一保存在一个子文件夹中，并有一个主索引文件"）

## 背景

项目进入设计定稿与后续 vibe coding 阶段，决策与变更若散落在对话里，面试叙述与回归排查都无据可查；需要可追溯的工程痕迹。

## 决策

1. 统一根目录 `docs/` 下分五区：`README.md`（主索引）、`design.md`（总设计）、`decisions/`（ADR）、`changes/`（CHG）、`research/`（只读调研）、`archify/`（自用架构可视化）。
2. 设计决策 → `decisions/ADR-NNN-短标题.md`；功能点更改 → `changes/CHG-NNN-短标题.md`；模板与维护约定见 `docs/README.md`。
3. 冲突裁决顺序：最新 ADR/CHG > design.md > research；ADR 废弃标注「被取代」不删除。

## 备选与否决理由

- **散放项目根目录**：检索差，决策与变更混在一起，无法回答"这个设计当时为什么这么定"。
- **单一 CHANGELOG 文件**：变更可记，但决策缺乏独立生命周期（状态/取代链），且长文件会腐化。

## 影响面

- 存量文档已归位：两份调研报告移入 `docs/research/`；`design.md` 入 `docs/`。
- 溯源补录：grill-me 九大决策补录为 ADR-001；本约定即 ADR-002。
- 后续所有文档写入后必须同步登记 `docs/README.md` 文档清单。
