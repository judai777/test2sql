# ADR-001：架构基线——grill-me 九轮拷打收敛决策

- 状态：**已接受**
- 日期：2026-08-28 拷打，2026-08-29 落档
- 决策方式：grill-me 逐分支拷打（一次一问、每问附推荐答案），用户逐项拍板；期间发生三次质疑/修正，复核后收敛
- 论据来源：`docs/research/` 两份调研报告
- 完整展开：`docs/design.md`

---

## D1 落地场景

- **决策**：证券/银行业务人员的自然语言取数助手，替代"向数据组提数工单"的流程。
- **背景**：用户金融科技实习的真实观察（客户为券商/银行，业务人员不熟 SQL）。
- **否决备选**：DBA 运维助手（偏离 Text2SQL 主线、评测难造）；自动报表看板（MVP 过重易烂尾）；多场景数据助手（范围失控）。
- **合规约束**：不使用任何真实客户数据；demo 库结构同构真实业务 + faker 合成数据。

## D2 执行范式

- **决策**：**ReAct 为核**；执行引擎做成"计划无关"（只知跑步骤/调工具/回填观察），二期快路径 = 强制计划模式注入同一引擎，零重构。
- **关键论据**：学习目标明确含 ReAct；BIRD 头部方案同为多步探索（难题上多步赢单发）；先通用引擎后特例的工作量优于反向。
- **质疑记录**：用户问"一开始就固定工作流是否更好"——以四点论证（学习目标硬需求 / 流水线是 ReAct 特例的包含关系 / 准确率证据 / 面试差异化）复核后**维持 ReAct**，分支关闭。
- **否决备选**：纯固定流水线（学习目标四个废两个）；纯自由 ReAct（管理层无价值、企业叙事弱）。

## D3 三层边界

- **决策**：路由层（意图分类/权限初检/会话绑定 → TaskRequest）→ 管理层（**纯确定性**：上下文装配、schema 召回、记忆读写、预算配置）→ 执行层（**唯一 LLM 所在**：ReAct 循环 + 工具 + 防护）。
- **否决备选**：管理层含 Planner（第二个 LLM 循环，与 ReAct 内部规划重叠）；不分层一个类全包（学习目标落空）。

## D4 工具集

- **决策**：五件套 `search_schema` / `get_schema` / `validate_sql` / `execute_sql` / `ask_user`。
- **亮点**：validate_sql 独立成工具——DB-GPT 未做完的一环（本项目增量），把"执行-报错"长循环压缩为"校验-修复"短循环（死循环防护的诱因消除类）。
- **裁剪**：sample_rows（涉客户数据脱敏）、few-shot/save_example（属记忆系统）均不入一期。

## D5 记忆系统

- **决策**：三层——短期会话窗口裁剪 ｜ 成功 QA 样例库（校验+执行双通过自动入库，few-shot top-3 检索）｜ 业务口径库（指标口径文档召回）。统一 MemoryStore 接口，检索失败降级直答。
- **明确裁掉**：Dream 式定时固化、经验流水位线、用户画像（通用助手机制，对本场景过度设计）。

## D6 死循环防护

- **决策**：四层 + 两附件——①步数上限（8~12）+ 耗尽无工具强制总结；②重复/振荡检测（同 tool+args 连续 ≥2 次警告、累计 ≥3 次强停）；③同一 SQL 错误回喂 ≤2 次；④墙钟超时（turn 120s / LLM 60s / 工具 30s）。附件：validate 前置；"转人工/提工单"降级接口一期留桩。
- **对齐认知**：六类全景（预算止损/打转识别/结构预防/元认知监视/回退恢复/诱因消除）已过一遍；裁判模型属④类进阶，入二期。
- **否决备选**：仅 max_steps 兜底（分不清进步与打转）；七层全上（token 预算与步数重叠）。

## D7 技术栈

- **决策**：**全自建轻量核**——httpx + pydantic 自写 OpenAI 兼容客户端（重试/超时/流式，模型配置化），sqlglot 校验，Chroma 向量，SQLite 存储，Python 3.11（uv 新环境）。
- **否决备选**：LangGraph 编排（循环成黑盒，学习对象被外包）；fork nanobot 改造（裁剪成本高，"读懂引擎"≠"造过引擎"）。

## D8 数据与评测

- **决策**：demo 库 faker 合成**百万行**；golden 集 50 条按"类型×难度"五档分层起步，随用户采纳闭环增长；指标用执行结果集比对 + 语法有效率 + 平均步数/成本；做记忆消融实验产出 Δ% 硬数字。
- **质疑记录**：用户质疑"50 条不符企业真实数据"→ 澄清测试集（分层代表性）与业务数据（行数量级）是两回事；**数据量级采纳用户意见提至百万行**（顺带激活 LIMIT/超时/索引话题）；同时堵住"用实习公司脱敏数据"的合规岔路。

## D9 驱动器与可视化

- **决策**：裸 REPL（~100 行）+ pytest 双驱动 + FastAPI 简易 Web（**用户加选**，接受约 2 天成本换业务叙事完整）；archify 架构图**纯自用**（用户修正：面试不演示项目，交付重心在代码质量与叙述）。
