# ADR-008：v2 架构迭代——双 agent、混合检索与记忆升级

- 状态：**已接受**
- 日期：2026-08-29
- 提出人：用户（基于实习中熟悉的企业级设计方案，经四轮讨论收敛）
- 性质：**演进而非重写**——v1 骨架（计划无关引擎、四层防护、只读护栏、审计、评测纪律、降级链）全部保留为脊柱；v2 的记忆/检索/双 agent 嫁接其上。每步迭代必须跑 golden 回归守住 78% 基线。

---

## D1 双 agent：data-analysis（主）+ coder（SQL 专职）

- **决策**：核心智能体收敛为两个。data-analysis 保留现有主循环（业务对话/schema 探索/澄清/结论）；**coder 接收上游传递的任务与 schema 信息，专职 SQL 编写与执行，经 MCP 调用数据库工具**；信息不足时 human-in-the-loop（复用 ask_user 通道，每 turn 限 2 次）。
- **MCP 双通道**：工具实现保持 Tool 类单一事实来源，用 fastmcp 包一层 MCP server 供 coder 调用（协议标准化、工具可被外部 client 复用、coder 权限面与主 agent 隔离）；data-analysis 主循环保持 in-process 直调（零协议延迟）。
- **安全红线延伸**：execute_sql 全部护栏（只读/黑名单/LIMIT/超时）实现在 Tool 类内部、随 MCP 通道天然继承——**换协议通道不换安全边界**。
- **实现约束**：两个 agent = 两份 skill 配置（`executor/skills/*.md`：system prompt + 工具白名单 + 预算 profile），**共享同一个计划无关引擎**——不写第二套循环（nanobot "core stays small; extend at the edges"）。
- **递归防护**：子 agent 预算从父 turn 预算内扣减，防 agent 套 agent 爆炸。

## D2 长期记忆：确认制 + 双类记忆

- **决策**：放弃全自动沉淀，采用**确认制**——双通过自动进**候选池**（qa_pairs.status=candidate），用户确认/拖入后进**正式库**（status=confirmed），检索只取正式库。
- **双类记忆**：①**结果表格记忆**（saved_results：question/SQL/columns/rows 样本，跨会话复用"上次那张表"）；②**字段 schema 记忆**（并入 D4 复用统计与既有口径库）。
- **时效性设计**：结果表格记录 created_at 并预留"重新执行刷新"（记忆的是可重放的计算，不是数据快照）——真实库数据漂移的对策。
- **理由**：避免自动加载大量无关历史；确认制同时保留自动化收集（消融实验证明样例覆盖率是记忆价值命门，纯手动会杀死它）。

## D3 混合检索：关键词主导、语义辅助

- **决策**：召回 = 关键词（主导，权重 0.7）∪ 语义（辅助，0.3），RRF 融合。
- **依据**：金融 schema linking 需要表名/字段名**精确定位**，业务术语高度规范化，词面命中精度最高；语义优先的失败模式（"成交额"漂移到"市值"）产生语法正确但口径错误的 SQL——**失败模式不对称，精度优先**。业界同构：BIRD 头部方案以精确实体匹配为主、embedding 辅助。
- **隐含前提**：词面命中依赖元数据语料质量（search_corpus 含中文注释+枚举值）。对策：从评测失败案例增量收集业务别名词表（轻资产），不建大词表。
- **范围**：search_schema 表召回与样例库检索均改为并联混合（v1 为互斥降级）。

## D4 表格与字段复用（Text2SQL 特有记忆层）

- **决策**：新增 `schema_usage` 统计表——`record_success` 时用 sqlglot 反解 SQL 得到 table/field 使用，累计 hits + last_used。
- **用途**：作为 rerank 的核心特征（复用频次加权），让高频业务表在 search_schema 中自然前置——用户行为反哺检索排序。
- **与口径库关系**：字段语义/口径条目仍在口径库（metrics_docs），复用统计只管"用得多不多"，不管"是什么意思"。

## D5 重排：接口化三实现，内网生产用 cross-encoder

- **决策**：`manager/rerank.py` 定义 Reranker 接口，三个实现：
  1. **HeuristicReranker**（默认）：复用频次 + 近因衰减 + 精确命中加权，零依赖，开发机/CI 直接跑；
  2. **CrossEncoderReranker**（内网生产）：bge-reranker-base ONNX int8（~280MB，CPU 20~80ms/对），`pip install ".[rerank]"` 可选依赖 + `T2S_RERANK_MODEL_PATH` 本地路径加载，**代码零自动下载**；
  3. **LLM 精排**：**否决**——内网合规要求下外部 API 数据出域不可接受，内网私有化 LLM 做重排则挤占共享 GPU 且不确定。
- **ADR-007 范围修正**：其否决的是"外部 CDN 自动下载的托管方案"；内网镜像前提下本地模型文件方案成立。本 ADR 显式修订该范围，接口化设计使两种部署形态（开发机/内网）共用一套代码。
- **管线**：召回（关键词∪语义，RRF）→ 重排（按部署形态选实现）→ top-k 注入。消融维度升级为三档：无记忆 / 启发式 / cross-encoder。

## D6 权限硬约束落地

- **决策**：PermissionRegistry 支持 per-user 表级白名单（frozenset），`execute_sql`/`validate_sql` 执行前用 sqlglot 提取实际访问表集合与白名单**代码级比对**，越权即硬边界拒绝（不可重试文案）。RouterService 按请求注入（dataclasses.replace 派生 ctx）。
- **定位**：v1 权限只有初检结构位（全员 readonly_all）；本决策把"用户权限"从提示词软约束升级为代码硬约束——金融场景必答点。

## D7 向量库企业形态：Milvus 适配（接口化，本机模拟内网）

- **背景**：私域并发评估确认向量检索非并发瓶颈（毫秒级 vs LLM 秒级多跳），但企业内网形态需要标准向量平台。用户约束：**无法接入公司内网，且本机 Windows 无 Docker、WSL 无发行版**。
- **事实约束**：Milvus 官方不支持 Windows 原生运行；Milvus Lite（嵌入式）仅 Linux/macOS。pymilvus 客户端跨平台（已装 3.0.1）。
- **决策**：
  1. 新增 `MilvusVectorStore`（pymilvus MilvusClient 适配层）——**同一客户端 API 同时覆盖 Milvus Lite 与 Standalone（Docker/生产）**；构造即探活（fail-fast），连不上抛 MilvusUnavailableError，上层降级 SQLite 自建向量；
  2. **三条部署路径**（按忠实度）：A. WSL2 装 Ubuntu + docker-ce（免 Docker Desktop）跑 standalone 容器，Windows 侧 localhost:19530 直连——网络边界/gRPC/连接串与生产一致，最忠实模拟；B. 接口换牌 Windows 原生向量库（Qdrant 单二进制 / PostgreSQL+pgvector）；C. 零服务模拟（SQLite JSON + 余弦，现状）——Milvus 适配层与门禁测试先落库，环境就绪一键启用；
  3. `deploy/docker-compose-milvus.yml` 备好官方 standalone 三容器形态；
  4. **接口不变，部署形态决定实现**：本机模拟的完整映射——LLM=Zhipu API 模拟内网 vLLM（base_url 配置化）、Embedding=Zhipu 模拟内网 bge、Reranker=启发式/本地 ONNX 模拟内网模型文件、向量库=SQLite 兜底 / Milvus 容器模拟内网平台、关系库=SQLite 模拟 PostgreSQL（storage 单一出口）。

## 保留项声明（v2 未提及但不可丢）

四层死循环防护、只读硬护栏（mode=ro/黑名单/LIMIT/超时）、全链路审计、降级链（转人工/提工单）、评测纪律（golden 回归守 78% 基线）、计划无关引擎。

## 里程碑

- **M7 检索与权限**：RRF 融合 + schema_usage + 启发式重排 + 权限硬约束
- **M8 记忆升级**：确认制（候选/正式库）+ 结果表格记忆 + 异步摘要
- **M9 双 agent 与内网重排**：skill 目录化 + coder 子 agent（MCP）+ 递归预算 + CrossEncoderReranker（需内网/本地模型文件）+ 全量回归

## 影响面

`manager/`（retrieval/rerank/memory）、`storage/`（schema_usage/saved_results/qa_pairs.status）、`executor/`（skills 目录化）、`tools/sql_tools.py`（权限比对）、`router/permissions.py`。评测报告基线 78% 为回归锚点。
